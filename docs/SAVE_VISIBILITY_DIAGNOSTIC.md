# DT_FldPlaceName і видимість сейвів

Проблему вирішено й підтверджено у грі. Поточна процедура:
[SAVE_PLACE_LOCALIZATION.md](SAVE_PLACE_LOCALIZATION.md). Нижче — історія діагностики.

Ігровими тестами користувача 10 жовтня 2026 підтверджено:

- контрольна збірка `20261008-102015`: усі сейви відображаються;
- тільки п'ять DT `Xrd777/Field`: видно лише комірки 2 і 13;
- тільки п'ять DT `Astrea/Field`: усі сейви відображаються;
- тільки `Xrd777/Field/Data/DataTable/Texts/DT_FldPlaceName`: видно два сейви;
- чотири інші DT `Xrd777/Field`, без `DT_FldPlaceName`: усі сейви відображаються.

Спільні ресурси кожного діагностичного комплекту порівняні за SHA-256
із контрольною збіркою. DT_FldPlaceName самостійно відтворює проблему.
Це ще не визначає, чи пошкоджена серіалізація, чи назви використовуються
грою в логіці обробки збережень.

Тимчасове рішення: `protected_resource_paths` у `config/build-exclusions.json`
виключає саме Xrd777 DT_FldPlaceName в базовому Content і всіх культурах.
`P3R_INCLUDE_DT_TEXT=1` не повертає цей ресурс. Переклад XML та uasset
збережені; гра використовує власну оригінальну таблицю назв місць.
Astrea DT_FldPlaceName залишається доступною для DT opt-in.
Раніше виключені DT_SystemTextName також залишаються виключеними.

Повний тестовий мод із рештою DT:

```bash
P3R_INCLUDE_DT_TEXT=1 ./scripts/linux/pack_linux.sh
```

Для дослідження саме цього випадку потрібні окремі тести, а не вилучення
перекладів: побайтово незмінний оригінал у такому самому контейнері;
потім одна зміна ASCII тієї самої довжини; потім одна UTF-16 зміна.
Три контрольні збірки підготовлені, ігрові результати ще очікуються. Вони відокремлять вплив пакування,
розміру, кодування та самого значення назви.


## Підготовлені проби

Незмінений ресурс отримано командою retoc get з pakchunk4 гри;
SHA-1 звірено з оригінальним індексом. Проби зберігаються в
`build/place-name-probes/`, робочий XML-переклад не змінюється.

- `original.uasset`: точна копія ігрового ресурсу, без імпорту.
- `ascii.uasset`: School Entranceway → School Entrancewax, рівно один
  змінений байт, розмір та кодування оригіналу збережені.
- `utf16.uasset`: той самий School Entrancewax у UTF-16LE; змінені
  FString length, StrProperty Size і єдиний Export SerialSize.
  У цій таблиці немає ArrayProperty/StructProperty контейнерів.
  Усі 891 розпізнаний рядок повторно читаються без інших змін.

Для контрольованих збірок додано явний параметр
`P3R_DIAGNOSTIC_ASSETS_FILE` з JSON, який містить словник `assets`:
ігровий шлях → файл проби. Він дозволяє включити цей ресурс попри
постійне виключення й примусово пакує незмінений оригінал.
Звичайні збірки без цього параметра зберігають захисне виключення.
Пакувальник записує параметри проби в reports/diagnostic-assets.json.


## Результати мінімальних проб

Користувач підтвердив: незмінений ігровий оригінал, один ASCII-байт,
те саме англійське значення у UTF-16 і один справжній український рядок
зберігають видимість усіх сейвів. Обидві групи по 445 перекладених
значень приховують сейви. Повний XML має 890 змінених значень; повторний
імпорт дає той самий SHA-256, що й проблемний підготовлений uasset.

Для відділення зміни значень від масового перерахунку розмірів
підготовлено дві проби: 890 незмінених англійських назв у UTF-16 і
890 однобайтових ASCII-правок зі збереженням розміру файла та всіх
property sizes. Ігрові результати цих двох проб поки очікуються.
Також готові дві частини першої проблемної групи (222 і 223 правки).


## Значення назв і експериментальні псевдоніми

Користувач підтвердив: всі 890 оригінальних назв у UTF-16 зберігають
видимість сейвів, а 890 однобайтових ASCII-правок без зміни кодування,
розмірів тегів або всього файла приховують сейви. Отже, цей випадок
не пояснюється лише масовим перерахунком розмірів/UTF-16.
Зв'язок назв із сумісністю сейвів підтверджений тестами; точний
алгоритм гри (ключ, перевірка чи зворотний пошук) ще не встановлений.

Незалежний структурний розбір таблиці знаходить 891 справжній рядок
із Index:IntProperty та Name:StrProperty. Історичний текстовий сканер
помилково розпізнає IntProperty Index=2 як короткий FString `o` і
через пропуск байтів не експортує наступну Name `School Building`.
Тому поточний XML має 890 перекладених назв, а School Building лишається
англійською. Відповідність цієї назви саме видимим сейвам не перевірена.

`tools/dt/place_name_alias_probe.py` створює тільки діагностичний
uasset у build/place-name-probes: 891 основний рядок із перекладом
і 890 англійських копій із тим самим Index та окремими numbered FName
ключами рядків. Основні рядки лишаються побайтово незмінними, всі
оригінальні пари Index/Name доступні у результаті. Це не звичайна
перекладацька збірка: сумісність duplicate Index, вибір назви для UI
та видимість сейвів ще мають бути перевірені у грі. Постійне захисне
виключення DT_FldPlaceName лишається чинним.


Першу alias-пробу користувач перевірив: усі сейви відображаються,
але назви в UI лишилися англійськими. Підготовлено варіант із тим самим
набором row keys/Index/Name і тільки іншим порядком серіалізації:
спершу основні українські рядки, потім англійські alias-рядки.
Порядок ще не підтверджено як механізм вибору назви у грі.
Команда генерації: `python3 tools/dt/place_name_alias_probe.py --translated-first`.


## SaveDataLocalize / DT_FldPlaceNameConvert

У вихідній грі знайдено базовий ресурс
`Xrd777/UI/Tables/SaveDataLocalize/DT_FldPlaceNameConvert`, не в L10N/en.
Структура NameNumberPairTable містить 11854 рядки Name:StrProperty та
Number:IntProperty (Number=0 може не серіалізуватися як default).
Таблиця містить назви всіма офіційними мовами; англійська назва
School Entranceway, наприклад, відповідає Number=1.
Number не завжди дорівнює прямому Index DT_FldPlaceName: назви повторюються
і нормалізуються, тож зв'язок встановлюється за оригінальним Name і
зберігає Number саме з конвертера, без вигадування нового коду місця.

`tools/dt/place_name_convert_probe.py` додає 890 українських пар до
оригінального конвертера. Усі 11854 попередні рядки залишаються
побайтово незмінними; для кожної зміненої англійської назви знайдено
відповідник у вихідному конвертері. У DT_FldPlaceName при цьому
використовується звичайний повний переклад без дублювання рядків.
Підготовлена проба змінює тільки ці два ресурси відносно підтвердженого
робочого мода. Ігровий результат ще очікується; постійне виключення
DT_FldPlaceName наразі не вимикається.
