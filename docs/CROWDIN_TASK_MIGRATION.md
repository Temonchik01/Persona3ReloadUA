# Перенесення завдань між гілками Crowdin

Скрипт `tools/crowdin/migrate_tasks.py` працює з Crowdin API v2 для файлових
проєктів. Він змінює тільки `/fileIds` у наявних завданнях, а не джерела чи
переклади. Інші параметри завдання не надсилаються для зміни; склад рядків і
відсоток виконання Crowdin може перерахувати для нових файлів.

Створіть особистий API-токен Crowdin з доступом до потрібного проєкту:
читання проєктів, вихідних файлів і гілок, читання та запис завдань.
Потрібна також роль, яка дозволяє редагувати завдання в проєкті.
Не записуйте токен у репозиторій або аргументи команди: скрипт запитає його
через приховане введення. Альтернатива — локальна змінна `CROWDIN_TOKEN`.

## 1. Інвентаризація (лише читання)

```bash
cd /home/tymofii/Persona3ReloadUA
python3 tools/crowdin/migrate_tasks.py inventory --project-slug persona-3-reload-ua
```

Збережіть показані числові Project ID, ID гілки «Чорнетка» та нової гілки
`Persona3ReloadUA / main`. Скрипт показує точні API-назви; вони можуть
відрізнятися від відображення в інтерфейсі.

## 2. План (лише читання)

Замініть числа прикладу фактичними ID з інвентаризації:

```bash
python3 tools/crowdin/migrate_tasks.py plan --project 123456 --from-branch 10 --to-branch 20 --output build/crowdin-tasks-plan.json
```

Для першого тесту лише завдання №6 додайте `--tasks 6`. Перевірте JSON:
старі та нові ID, шляхи файлів, назви завдань, `errors` і `skipped_tasks`.
У плані немає токена. Зіставлення точне та враховує регістр; пошук лише за
назвою файла не використовується. Завдання з directory-, branch- або
string-scoped набором файлів пропускаються і зазначаються у звіті.

## 3. Застосування перевіреного плану

```bash
python3 tools/crowdin/migrate_tasks.py apply build/crowdin-tasks-plan.json --confirm
```

Перед змінами скрипт повторно перевіряє всі завдання та відповідники.
Плани з помилками не застосовуються. Якщо завдання змінено після планування,
сформуйте новий план. Після кожного PATCH скрипт читає результат і перевіряє
ID файлів. Масова операція не є транзакцією: якщо запит не вдався посередині,
раніше успішно змінені завдання залишаються перенесеними. Перегляньте вивід
і сформуйте новий план, перш ніж продовжувати.

Не видаляйте стару гілку, поки не перевірено результати перенесення.
Оригінальні параметри завдань зберігаються в `snapshot` файлу плану.

Документація API: https://support.crowdin.com/developer/api/v2/
