# Backup and Restore

Перед операцією, яка може перезаписати ресурси або джерела, створюй окрему копію саме цільових файлів. Попередній готовий мод і весь репозиторій резервувати не потрібно.

Скрипти наразі не створюють резервні копії автоматично.

## Коли робити копію

Перевір цільові шляхи команди. Типові приклади:

| Операція | Можливі цілі для резерву |
|---|---|
| Експорт BMD XML | `xml/` |
| Експорт DT XML | `dt_xml/` |
| Експорт DDS або оновлення DDS з PNG | `texture/dds/` |
| Імпорт BMD | відповідні ресурси в `UnrealEssentials/` |
| Імпорт DT | відповідні ресурси в `UnrealEssentials/` |
| Імпорт DDS | відповідні ресурси в `UnrealEssentials/` |

Звичайне пакування створює нову версію в `dist/`; воно не потребує резервної копії попереднього комплекту, якщо перед ним не запускали операцію, що змінює вихідні файли.

## Створення

1. Запиши назву операції й точний список файлів, які вона може змінити.
2. Створи каталог `workspace/backups/<YYYY-MM-DD_HH-mm-ss>/`.
3. Скопіюй лише цільові файли, зберігаючи їхні відносні шляхи від кореня репозиторію.
4. Створи маніфест з часом, назвою операції, відносними шляхами файлів, розмірами та SHA-256.
5. Перевір копії та їхні контрольні суми до запуску операції.

Приклад для Linux із заздалегідь переліченими файлами:

```bash
backup="workspace/backups/$(date +%Y-%m-%d_%H-%M-%S)"
mkdir -p "$backup"
cp --parents path/to/file1 path/to/file2 "$backup/"
sha256sum path/to/file1 path/to/file2 > "$backup/manifest.sha256"
```

Підстав лише фактичні цільові шляхи відповідної операції.

## Відновлення

1. Зупини подальші імпорти й пакування.
2. Вибери резерв за часовою позначкою та звір його маніфест.
3. Скопіюй потрібні файли назад до початкових відносних шляхів.
4. Перевір SHA-256 відновлених файлів.
5. Зафіксуй результат у звіті відповідної збірки.

Каталог `workspace/` виключений із Git і не очищається звичайною збіркою. Резерви не видаляються автоматично; очищай їх вручну після підтвердження, що відновлення більше не потрібне.
