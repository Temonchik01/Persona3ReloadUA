# Автоматичне збирання мода на Linux

Запустіть із кореня репозиторію:

```bash
./scripts/linux/build_mod.sh
```

Скрипт також працює з іншого каталогу, якщо вказати його повний шлях.
Джерела визначаються відносно самого скрипта:

- translations/uk/dt_xml/ — українські DT XML;
- translations/uk/xml/ — українські BMD XML;
- dds/ — перекладені текстури.

Кореневі xml/ та dt_xml/ — джерела Crowdin, для українського імпорту не використовуються.
Папки tools/dt/source/ і tools/dds_l10n/source/ містять оригінальні шаблони ресурсів;
вони потрібні для імпорту та не є джерелами українського тексту.

Послідовність:

1. Перевірка наявності папок, залежностей, XML та закритої гри.
2. Перебудова нативного DT-інструмента з поточного C# коду.
3. Імпорт усіх DT XML із --force.
4. Імпорт усіх BMD XML із --force через Wine.
5. Імпорт DDS.
6. Пакування зі звичайними правилами та автоматичними відповідниками назв
   локацій і системних значень для відображення сейвів.
7. Перевірка трьох файлів .pak/.ucas/.utoc у mod/ та ZIP.

Виконавці: Python 3, .NET 8 SDK, Wine, winepath, timeout, prlimit, tee,
а також інструменти репозиторію. Шляхи гри й retoc використовуються з
config.local.env або типових налаштувань pack_linux.sh. DDS з іншим DXGI
форматом можуть потребувати libtexconv.so.

Вхідні переклади не змінюються. Імпорт записує ресурси в UnrealEssentials/,
пакувальник публікує dist/<час>/Persona3ReloadUA.zip та mod/ із трьома файлами.
Новий архів не встановлюється автоматично в гру.

У разі помилки показуються назва етапу, код завершення або повідомлення
інструмента й шлях до журналу. Наступні етапи не запускаються. Частково
імпортовані ресурси можуть залишитися в UnrealEssentials/, тому після
виправлення причини запустіть весь скрипт повторно, а не лише пакувальник.
Імпорт --force заново перебудує наявні вхідні XML.

Журнали кожного запуску зберігаються окремо:

```text
build/logs/full-build-<час>.<id>/
  preflight.log
  dt-tool.log
  dt.log
  bmd.log
  dds.log
  pack.log
```

Скрипт також зупиняється, якщо інструмент повернув нульовий код, але
повідомив про FAIL або ненульову кількість errors у виводі.
Старі діагностичні змінні оточення очищаються перед збиранням. Не задавайте
діагностичні режими в config.local.env для звичайного випуску.

Системні сейв-відповідники описані в SAVE_SYSTEM_LOCALIZATION.md.
Звичайне правило виключення DT_DlcBgm залишається чинним.

Довідка:

```bash
./scripts/linux/build_mod.sh --help
```


Цей процес і нові DT-виправлення перевірені для нативного Linux-інструмента.
Постачаний Windows EXE окремо не перебудовувався; перед збиранням DT на Windows
потрібно скомпілювати актуальний C# код і перевірити імпорт.
