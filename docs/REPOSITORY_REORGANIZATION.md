# План упорядкування репозиторію без втрати перекладів

Цей документ — план. Папки, гілки й конфігурація Crowdin не переміщені.

## Поточні межі

GitHub має main та l10n_main. Це підтверджено через GitHub connector.
Локально збережені origin/main і origin/l10n_main відрізняються файлами
перекладів, DDS та іншими матеріалами. Порівняння може не включати найновіші
віддалені коміти: перед реалізацією потрібно оновити remote refs.
Не скидати й не переписувати l10n_main під main.

crowdin.yml в обох локальних refs однаковий:

- джерела BMD: /xml/**/*.xml;
- джерела DT: /dt_xml/**/*.xml;
- результати: /translations/%two_letters_code%/xml/**/%original_file_name%
  та відповідний шлях dt_xml.

За наданим користувачем скріншотом налаштувань GitHub integration:

- main вибрана як Branch for Translation — джерело синхронізації;
- l10n_main задана як Service Branch Name — службова гілка;
- l10n_main не вибрана як окрема гілка для перекладу;
- Always import new translations from the repository увімкнено;
- Push Sources вимкнено;
- Sync Schedule увімкнено, інтервал 24 години;
- Branches to Sync Automatically: *translate*;
- Configuration File Default Name: crowdin.yml.

Це фіксація скріншота, а не незалежна перевірка живої інтеграції.
Не додавати l10n_main як другу гілку перекладу й не перейменовувати її.
Через імпорт перекладів із репозиторію не змінювати translations/ під
час упорядкування. Поточний стан PR/merge бота на скріншоті не показаний.

## Рекомендований перший етап

Зберегти назви та вміст xml/, dt_xml/, translations/, dds/, tools/,
UnrealEssentials/, crowdin.yml. Це зберігає існуючі контракти шляхів.

1. Доповнити README: карта папок, робота перекладача, Windows/Linux,
   підготовка релізу, порядок XML -> uasset -> pak/utoc/ucas.
2. Зібрати інструкції в docs/, залишити посилання зі старих місць.
3. Додати scripts/ як зручну точку запуску. Спочатку використовувати
   обгортки існуючих кореневих скриптів, не переносити їхні реалізації.
   Просте перенесення BAT ламає %~dp0, а SH — обчислення кореня.
4. Додати .gitignore для artifacts/, Wine-префіксів, журналів і кешів
   Python. Не ігнорувати переклади або раніше відстежувані мод-ресурси.
5. Розділити результати збирання та релізні пакети; старий вихідний
   шлях UnrealEssentials зберегти до окремого узгодженого переходу.
6. Уніфікувати пошук кореня проєкту й конфігурацію інструментів.
   Прибрати персональні шляхи /home/tymofii з типових запусків,
   використовуючи налаштування користувача поза Git.
7. Забезпечити відтворюване пакування шрифтів. Поточний Linux-пакувальник
   залежить від FONT_PAK або локального тестового артефакту; після
   ігнорування artifacts цей залежний файл треба створювати або явно
   надавати, інакше свіжий клон не збереться.
8. Додати перевірку шляхів, синтаксису скриптів і XML у CI; виконувані
   Windows-компілятори й реальну синхронізацію перевіряти окремо.

## Перевірки перед публікацією

- Зберегти список/хеші джерел і перекладів до змін. Вони не повинні
  змінитися через упорядкування.
- Порівняти набори файлів, що відповідають glob-шаблонам crowdin.yml.
- Перевірити імпорт одного BMD та однієї DT, експорт/імпорт DDS,
  збирання двох уже підтверджених ресурсів через retoc.
- Перевірити старі й нові команди з іншої робочої папки та шляху
  з пробілами на Windows і Linux.
- Перевірити свіжий клон без локальних artifacts і особистих налаштувань.
- Після узгодженого merge перевірити один цикл Crowdin: джерело,
  експорт перекладу, гілка/PR, незмінні шляхи й наявність перекладів.

## Якщо пізніше переносити XML

Це окрема міграція. Потрібні узгоджені зміни source/translation у
crowdin.yml, вебналаштувань інтеграції та компіляторів, зі збереженням
історії файлів у Crowdin. Git-перенесення саме по собі не підтверджує
збереження історії, перекладів та схвалень на стороні Crowdin.
Не перейменовувати гілки й не додавати preserve_hierarchy навмання.

## Робота з гілками

Реалізацію готувати в окремій гілці codex/repository-organization від
актуальної main, з окремо збереженими незакоміченими правками.
Не переносити локальні переклади або величезні тестові пакети до PR
упорядкування. Не застосовувати reset/force-push до l10n_main.
Службові зміни готувати для main. Потрапляння їх до l10n_main перевірити
під час циклу синхронізації Crowdin; не робити автоматичний merge усіх
відмінностей гілок і не переписувати службову гілку вручну.
