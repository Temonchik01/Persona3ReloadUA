# Збирання на Fedora

Закрийте гру. Із папки проєкту спочатку зберіть змінені XML:

```bash
./scripts/linux/repack_linux.sh bmd
./scripts/linux/repack_linux.sh dt
```

Потім запакуйте готові ресурси:

```bash
./scripts/linux/pack_linux.sh
```

Типова вхідна папка — `UnrealEssentials`, із деревом `P3R/Content/...`.
Можна вказати іншу папку, що містить таке дерево:

```bash
./scripts/linux/pack_linux.sh /path/to/asset-only/UnrealEssentials
```

Скрипт бере таблиці й усі ресурси з оригінальних контейнерів гри та
замінює тільки надані uasset. Нічого не синтезує вручну. Працює послідовно,
обмежує пам'ять retoc до 1536 МіБ та кожну команду до 900 секунд.
Відсутній ресурс або помилка перевірки зупиняють збирання.

Кожен задіяний оригінальний контейнер створює окремий комплект.
Результат: `artifacts/pak-builds/<час>/pakchunk999-UA00_P.*` тощо.
Скопіюйте тільки `.pak`, `.utoc`, `.ucas` у `P3R/Content/Paks/~mods`,
попередні тестові комплекти перенесіть у резервну папку. Виберіть English.
Скрипт сам не встановлює мод.

Цей перевірений метод перепаковує контейнер цілком без стиснення.
Файли великі: тестовий контейнер давав близько 2,2 ГБ UCAS; поруч також
залишається raw-копія. Для повного мода потрібно багато вільного диска.

Шрифти: використовується вже перевірений companion PAK
`tools/iostore/fonts.pak`. Нові ufont/TTF скрипт
не збирає. Вхід підтримує uasset, ubulk і uptnl. Незмінені шрифти з попереднього
комплекту перевіряються й беруться з готового PAK; інші файли викликають помилку,
щоб вони не були мовчки пропущені. Змінені шрифти треба окремо зібрати
через repak і передати готовий PAK через FONT_PAK.

Шляхи та обмеження можна змінити:

```bash
RETOC=/path/to/retoc GAME_PAKS=/path/to/P3R/Content/Paks \
FONT_PAK=/path/to/fonts.pak P3R_PACK_MEMORY_MB=1536 \
P3R_PACK_TIMEOUT=900 ./scripts/linux/pack_linux.sh
```

AES-ключ заданий у допоміжному скрипті. Верифікація включає retoc verify
і порівняння SHA256 кожного підставленого ресурсу після його витягування.
Журнали та replacements.json зберігаються поряд з результатом.
