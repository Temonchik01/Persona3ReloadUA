# Persona3ReloadUA

Українська локалізація та мод для **Persona 3 Reload**. Проєкт охоплює переклад BMD-діалогів і DT-таблиць, текстури, шрифти, імпорт і пакування ресурсів гри.

Мод замінює англійську мову гри. Готовий для встановлення комплект складається з трьох файлів: `.pak`, `.utoc` і `.ucas`.

## Зміст репозиторію

| Шлях | Призначення |
|---|---|
| `xml/` | Англомовні BMD XML-джерела для Crowdin |
| `dt_xml/` | Англомовні DT XML-джерела для Crowdin |
| `translations/uk/xml/` | Українські переклади BMD |
| `translations/uk/dt_xml/` | Українські переклади DT |
| `texture/dds/` | Робочі текстури DDS |
| `texture/png/` | PNG для редагування та конвертації |
| `texture/sources/` | PSD, XCF та інші вихідники з шарами |
| `texture/originals/` | Збережені оригінальні DDS |
| `fonts/` | Матеріали шрифтів |
| `UnrealEssentials/` | Імпортовані ресурси мода за ігровими шляхами |
| `dev/instruments/` | Вихідний код інструментів C# |
| `dev/tools/` | Інструменти проєкту, бібліотеки та вихідні шаблони ресурсів |
| `dev/scripts/linux/` | Скрипти для Linux |
| `dev/scripts/windows/` | BAT-скрипти для Windows |
| `dev/gui/` | Графічний інтерфейс для тесту текстур і повної збірки |
| `docs/` | Детальні процедури та технічні примітки |
| `build/` | Тимчасові файли, журнали та результати перевірок |
| `dist/` | Готові комплекти мода, ZIP і звіти |
| `workspace/` | Локальні експорти, кеші, резервні копії й робочі матеріали |

Не переміщуйте інструменти або XML-каталоги окремо: скрипти очікують саме ці шляхи.

## Джерела та переклади

`xml/` і `dt_xml/` містять оригінальні джерела для Crowdin. Не редагуйте їх як український переклад.

Переклад редагується у файлах `translations/`. Синхронізація з Crowdin **необов’язкова для кожної зміни**: виконуйте її, якщо відповідний переклад у Crowdin відсутній або застарів.

Якщо синхронізація потрібна:

1. Завантажте локальний переклад із `translations/` до Crowdin.
2. Синхронізуйте переклад у Crowdin.
3. Завантажте актуальний варіант назад у `translations/` з урахуванням інших змін.
4. Перевірте файли й запустіть потрібний імпорт або збірку.

У Crowdin джерельною гілкою є `main`, а `l10n_main` — службова гілка інтеграції. Не реєструйте `l10n_main` як другу гілку перекладу й не перезаписуйте її вручну.

Шляхи BMD-інтеграції:

- джерело: `/xml/**/*.xml`
- переклад: `/translations/%two_letters_code%/xml/**/%original_file_name%`

DT-джерела зберігають оригінальний `Source` і значення `Translation`, що відповідає джерельному тексту. В українських DT XML зберігайте структуру: оригінальний `Source` і переклад у `Translation`.

Не змінюйте керівні коди BMD та технічні ключі DT. Детальні процедури: [BMD/Crowdin workflow](docs/BMD_CROWDIN_WORKFLOW.md) і [DT/Crowdin workflow](docs/DT_CROWDIN_WORKFLOW.md).

## Текстури

PSD/XCF та інші багатошарові вихідники спершу експортуються у PNG. Перед повною збіркою PNG потрібно конвертувати у DDS.

У повній збірці готовий DDS має пріоритет над однойменним PNG. Якщо DDS відсутній, PNG може бути конвертований під час збірки. Після редагування PNG заздалегідь оновіть відповідний DDS або скористайтеся режимом `--convert-png`.

Конвертація використовує формат і параметри оригінального ресурсу, де це можливо. Не використовуйте довільний DDS як зразок. Деталі про формати, альфа-канал і якість стиснення наведені в [DDS pipeline](docs/DDS_L10N_PIPELINE.txt) та [редагуванні PNG](docs/IMAGE_TO_DDS.md).

## Перед роботою

- Закрийте гру перед експортом та імпортом ресурсів.
- Для персональних шляхів гри й шрифтів використовуйте `config.local.env`, створений на основі `config.local.env.example`. Не додавайте його до Git.
- Перевіряйте, що обрано правильний каталог перекладів і правильні вихідні папки.
- Деякі `export_*` команди можуть перезаписати XML або текстури. Перед такою операцією збережіть цільові файли в окремій резервній папці. Скрипти поки не створюють резервних копій автоматично.
- Не встановлюйте проміжні контейнери чи неповний результат збірки.

## Linux

### Вимоги

Для повного автоматичного збирання потрібні:

- Python 3;
- .NET SDK, сумісний із проєктом `P3RDtTool`;
- Wine і `winepath` для BMD-інструмента;
- `timeout`, `prlimit` і `tee`;
- Linux-версія `retoc`;
- встановлена Persona 3 Reload.

Для конвертації деяких DDS-форматів може знадобитися `libtexconv.so`.

Скрипти шукають Linux retoc у `dev/tools/iostore/bin/retoc` або за шляхом із змінної `RETOC`. Після нового клонування цю локальну бінарну директорію може знадобитися підготувати окремо.

### Повна збірка

Запускайте з кореня репозиторію:

```bash
./dev/scripts/linux/build_mod.sh
```

У терміналі скрипт пропонує конвертувати PNG у DDS:

- `1` — конвертувати PNG перед збіркою;
- `2` або Enter — використовувати наявні DDS.

Неінтерактивний режим:

```bash
./dev/scripts/linux/build_mod.sh --convert-png
./dev/scripts/linux/build_mod.sh --skip-png
```

Повна послідовність:

1. Перевірка залежностей, XML та стану гри.
2. Збирання DT-інструмента.
3. Імпорт українських DT XML.
4. Імпорт українських BMD XML через Wine.
5. Імпорт текстур DDS.
6. Пакування й перевірка комплекту.

Якщо етап завершується помилкою, наступні етапи не запускаються. Частково імпортовані ресурси можуть залишитися в `UnrealEssentials/`. Після виправлення проблеми запустіть повну збірку знову, щоб повторно обробити потрібні джерела.

Довідка:

```bash
./dev/scripts/linux/build_mod.sh --help
```

### Окремі етапи

Імпорт BMD:

```bash
./dev/scripts/linux/repack_linux.sh bmd
```

Імпорт DT:

```bash
./dev/scripts/linux/repack_linux.sh dt
```

Імпорт BMD з явно вказаної папки:

```bash
./dev/scripts/linux/repack_linux.sh bmd "$PWD/translations/uk/xml"
```

Імпорт лише DT text:

```bash
./dev/scripts/linux/repack_dt_text.sh
```

Експорт DDS створює нову робочу папку в `workspace/dds-exports/`:

```bash
./dev/scripts/linux/export_dds.sh
```

Імпорт відредагованих DDS:

```bash
./dev/scripts/linux/repack_dds.sh "$PWD/texture/dds"
```

Пакування підготовлених ресурсів:

```bash
./dev/scripts/linux/pack_linux.sh
```

Для альтернативного дерева ресурсів:

```bash
./dev/scripts/linux/pack_linux.sh /path/to/UnrealEssentials
```

Змінні `RETOC`, `GAME_PAKS`, `FONT_PAK`, `P3R_PACK_MEMORY_MB` і `P3R_PACK_TIMEOUT` можна задати у `config.local.env` або передати під час запуску. Приклад:

```bash
RETOC=/path/to/retoc \
GAME_PAKS=/path/to/P3R/Content/Paks \
FONT_PAK=/path/to/fonts.pak \
P3R_PACK_MEMORY_MB=1536 \
P3R_PACK_TIMEOUT=900 \
./dev/scripts/linux/pack_linux.sh
```

### Збирання GUI

```bash
./dev/scripts/linux/build_gui.sh
```

## Windows

Windows підтримує окремі імпортні й експортні BAT-скрипти, а повна збірка доступна через GUI. Повний Windows pipeline потрібно перевірити на чистому середовищі.

### Інструменти Windows

Інструменти, розроблені для цього проєкту, зберігаються у репозиторії. Єдина окрема стороння утиліта, потрібна для пакування Windows, — `retoc`.

Завантажте Windows x64-версію зі [сторінки релізів retoc](https://github.com/trumank/retoc/releases), перевірте опубліковану там контрольну суму та розмістіть виконуваний файл тут:

```text
dev/tools/iostore/bin/retoc.exe
```

Зафіксуйте використану версію й checksum. Зберігайте ліцензійне повідомлення upstream поруч із копією retoc. Сумісність вибраного релізу з пакуванням P3R перевіряйте перед його рекомендованим використанням. Детальніше: [Windows Tool Setup](docs/WINDOWS_TOOL_SETUP.md).

### GUI

Встановіть Python 3.11+ із Tkinter. Якщо Pillow відсутній, запустіть:

```text
dev/scripts/windows/install_gui_dependencies.bat
```

Запуск GUI:

```text
dev/scripts/windows/build_gui.bat
```

Windows GUI потребує Windows-версії `retoc.exe`, шрифтового пакета, інструментів репозиторію та встановленої гри. Документація GUI вказує .NET 8 SDK; звірте вимогу з актуальними цільовими версіями C# проєктів.

### Імпорт та експорт через BAT

Запускайте BAT-файли з `dev/scripts/windows/`:

| Файл | Дія |
|---|---|
| `repack_bmd.bat` | Імпорт українських BMD XML у ресурси мода |
| `repack_dt.bat` | Імпорт українських DT XML |
| `repack_dds.bat` | Імпорт DDS у дозволені ігрові шляхи |
| `export_bmd_xml.bat` | Експорт BMD XML у `xml/` |
| `export_dt_xml.bat` | Експорт DT XML у `dt_xml/` |
| `export_dds.bat` | Експорт DDS у `texture/dds/` |

Експортні команди можуть перезаписати цільову папку. Перед запуском збережіть відповідні файли у `workspace/backups/<дата-час>/`.

Окремого BAT-пакувальника повного Windows-мода немає. Для повної збірки використовуйте GUI після встановлення потрібних інструментів.

## Результати збірки

Успішна збірка створює:

```text
dist/<timestamp>/mod/
  pakchunk999-Ukrainian_P.pak
  pakchunk999-Ukrainian_P.utoc
  pakchunk999-Ukrainian_P.ucas
```

Поруч зберігаються ZIP і звіти збірки. Кожен запуск отримує окрему папку. Незавершені результати з `dist/<timestamp>.pending/` не встановлюйте.

Після повідомлення `Completed` перевірте, що `mod/` містить рівно три файли `.pak`, `.utoc` і `.ucas`, а ZIP відповідає цьому комплекту.

### Встановлення для перевірки в грі

1. Закрийте гру.
2. Видаліть попередній комплект мода з `P3R/Content/Paks/~mods`.
3. Скопіюйте лише три файли з `dist/<timestamp>/mod/` до `~mods`.
4. Запустіть гру англійською мовою.

Збірка та перевірка в грі — різні етапи. Успішне пакування означає, що комплект створений і пройшов автоматичні перевірки; воно саме по собі не підтверджує правильне відображення всіх змін.

Обсяг ігрової перевірки залежить від збірки:

- текстурна — перевірте вигляд змінених текстур;
- перекладна — перевірте відповідні меню, діалоги або рядки;
- повний мод — перевірте текст, текстури, шрифти й завантаження збережень.

У короткому звіті на кожну збірку зафіксуйте дату, платформу, тип збірки, артефакти, перевірені пункти, тестувальника й проблеми. Статуси: `працює`, `проблема`, `потрібно переробити`, `не тестувалося`.

## Резервні копії перед змінами

Скрипти не створюють резервні копії автоматично. Перед операцією, яка перезаписує файли, збережіть лише її цільові файли в:

```text
workspace/backups/<YYYY-MM-DD_HH-mm-ss>/
```

Збережіть початкові відносні шляхи та маніфест із назвою операції, переліком файлів, розмірами й SHA-256. Не видаляйте резерв автоматично. Детальна процедура: [Backup and Restore](docs/BACKUP_AND_RESTORE.md).

## Локальні та згенеровані файли

`build/`, `dist/`, `.cache/` і `workspace/` не додаються до Git:

- `build/` містить журнали, тимчасові дані й результати невдалих збірок;
- `dist/` містить готові комплекти, ZIP і звіти;
- `.cache/` містить локальні кеші інструментів;
- `workspace/` містить експорти, кеші текстур і резервні копії.

Робочі переклади та вихідники залишаються у своїх папках і не очищаються повною збіркою. Успішне пакування видаляє лише тимчасові файли відповідного запуску.
